# StatusApp — системный монитор в строке меню macOS

Дата: 2026-10-15
Статус: дизайн согласован, ожидает ревью спецификации

## 1. Цель

Лёгкое нативное приложение для строки меню macOS (рядом с часами), которое помогает:

1. **Ловить проблемы** — видеть, какой процесс грузит CPU/память, получать уведомление при перегреве, высокой нагрузке, нехватке памяти или места на диске.
2. **Видеть динамику** — мини-графики всех метрик за последние 10 минут.

Критерии успеха:

- По одному взгляду на строку меню понятно, всё ли в порядке (значения подсвечиваются красным при превышении порога).
- По клику — все метрики с графиками и список самых «тяжёлых» процессов.
- Само приложение почти не потребляет ресурсов: < 50 МБ RAM, < 1 % CPU в среднем при интервале 2 с.
- Недоступная метрика показывается как «—» и не роняет приложение.

Не цели (YAGNI): публикация в App Store, нотаризация, запись истории на диск, экспорт данных, поддержка Intel-маков (не запрещена, но не тестируется), локализация кроме русского.

## 2. Окружение и ограничения

- Mac на Apple Silicon (arm64), macOS 27; минимальная поддерживаемая версия — macOS 14 (нужен `@Observable`).
- Требуется установленный Xcode (активирован через `xcode-select`): в одних Command Line Tools не работают ни Swift Testing (нет плагина `TestingMacros`), ни XCTest — проверено. Проект при этом остаётся SwiftPM-пакетом без `.xcodeproj`: сборка `swift build`, тесты `swift test`, упаковка в `.app` скриптом, подпись ad-hoc (`codesign -s -`). Открывать в Xcode можно как пакет (`Package.swift`).
- Приложение для личного использования. Используются приватные/недокументированные API IOKit (температуры, SMC, GPU) — они могут сломаться при обновлении macOS; это допустимо при условии graceful degradation.
- Без root-прав часть процессов (принадлежащих root/другим пользователям, например `WindowServer`, `kernel_task`) может быть недоступна для чтения статистики — такие процессы пропускаются. Известное ограничение.

## 3. Архитектура

Подход: AppKit `NSStatusItem` (строка меню — нужен цветной текст и кастомный мини-график) + SwiftUI внутри `NSPopover` (панель и настройки) + Swift Charts (графики).

### 3.1 Структура пакета

```
Package.swift
Sources/
  CPrivateAPI/            C-таргет: объявления приватных IOKit-функций (IOHIDEventSystemClient*, структуры SMC)
    include/CPrivateAPI.h
    shim.c
  MetricsCore/            библиотека без UI, вся тестируемая логика
    Model/                Snapshot и типы метрик
    Collectors/           по одному файлу на сборщик
    Util/                 RingBuffer, RateCalculator, Formatters
    Alerts/               AlertRule, AlertEngine (без доставки уведомлений)
  StatusApp/              исполняемый таргет: AppKit/SwiftUI
    App/                  main, AppDelegate
    Sampling/             Sampler (actor), MetricsStore
    MenuBar/              StatusItemController, рендер строки меню
    Popover/              PopoverView и вкладки
    Settings/             SettingsStore, SettingsView
    Notifications/        UserNotificationNotifier (реализация AlertNotifier)
Tests/
  MetricsCoreTests/
Resources/
  Info.plist              LSUIElement = YES (нет иконки в Dock)
scripts/
  build-app.sh            swift build -c release → build/StatusApp.app → codesign ad-hoc
```

### 3.2 Сборщики (`MetricsCore/Collectors`)

Общий контракт:

```swift
protocol MetricCollector {
    associatedtype Value
    mutating func sample() -> Value?   // nil = метрика недоступна
}
```

Сборщики с состоянием (CPU, сеть, диск, процессы) хранят предыдущие счётчики и считают дельту; первый вызов возвращает `nil` для скоростей/процентов.

| Сборщик | Значение | Источник |
|---|---|---|
| `CPUCollector` | общая загрузка %, P-кластер %, E-кластер %, загрузка по каждому ядру | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)`; число P/E ядер — `sysctl hw.perflevel0.logicalcpu` / `hw.perflevel1.logicalcpu` (P-ядра идут первыми) |
| `MemoryCollector` | всего, использовано, app/wired/compressed/cached, давление (normal/warning/critical), swap used/total | `host_statistics64(HOST_VM_INFO64)`, `sysctl hw.memsize`, `sysctl vm.swapusage`, `sysctl kern.memorystatus_vm_pressure_level` |
| `SensorCollector` | список температурных датчиков (имя, °C), агрегаты «CPU» и «GPU» (максимум по группе), обороты вентиляторов, мощность системы (Вт) | `IOHIDEventSystemClient` с фильтром PrimaryUsagePage 0xff00 / Usage 5 (температуры); AppleSMC: ключи `FNum`, `F{n}Ac` (вентиляторы), `PSTR` (мощность) |
| `GPUCollector` | загрузка GPU % | IORegistry, класс `IOAccelerator`, словарь `PerformanceStatistics` → `Device Utilization %` |
| `NetworkCollector` | скорость ↓/↑ (байт/с), суммарно с запуска, имя активного интерфейса | `getifaddrs` + `if_data` (`ifi_ibytes`/`ifi_obytes`), исключая `lo0`; основной интерфейс — по наибольшему трафику / `SCDynamicStore` |
| `DiskCollector` | чтение/запись (байт/с), список томов со свободным/общим местом | IORegistry `IOBlockStorageDriver` → `Statistics` (`Bytes (Read)`/`Bytes (Write)`); тома — `FileManager.mountedVolumeURLs` + `volumeAvailableCapacityForImportantUsage` |
| `BatteryCollector` | заряд %, заряжается/от сети, циклы, здоровье % (MaxCapacity/DesignCapacity), мощность Вт (Voltage × Amperage) | `IOPSCopyPowerSourcesInfo`, IORegistry `AppleSmartBattery`; на десктопе — `nil` |
| `ProcessCollector` | список процессов: pid, имя, CPU %, память (phys footprint) | `proc_listallpids` + `proc_pid_rusage(RUSAGE_INFO_V4)`; время CPU в mach-тиках переводится через `mach_timebase_info`; процессы, которые не удалось прочитать, пропускаются |

### 3.3 Модель данных

```swift
struct Snapshot: Sendable {
    let timestamp: Date
    var cpu: CPUStats?
    var memory: MemoryStats?
    var sensors: SensorStats?
    var gpu: GPUStats?
    var network: NetworkStats?
    var disk: DiskStats?
    var battery: BatteryStats?
    var processes: [ProcessInfoRow]?   // заполняется, только когда панель открыта
}
```

### 3.4 Поток данных

```
Timer (интервал из настроек) → Sampler (actor, фоновый) → Snapshot
    → MetricsStore (@MainActor, @Observable): кольцевые буферы на 10 минут
    → AlertEngine.evaluate(snapshot, now) → [AlertEvent] → AlertNotifier
    → StatusItemController / PopoverView перерисовываются по наблюдению
```

- `Sampler` опрашивает сборщики последовательно; каждый вызов сборщика обёрнут так, что ошибка даёт `nil`, не прерывая остальных.
- Пока панель открыта, интервал сокращается до 1 с и включается `ProcessCollector`; при закрытии — возврат к интервалу из настроек, процессы не опрашиваются.
- `MetricsStore` хранит `RingBuffer<Double>` для каждой графической серии: CPU total, P, E, по ядрам, память used, температура CPU, GPU, сеть ↓/↑, диск R/W. Ёмкость = 600 с / интервал (300 точек при 2 с). При смене интервала буферы пересоздаются (история сбрасывается — допустимо).
- Последний полный `Snapshot` хранится для отображения текущих значений.

## 4. Интерфейс

### 4.1 Строка меню (`StatusItemController`)

Отображаемые элементы включаются галочками в настройках; порядок фиксированный:

1. иконка (SF Symbol `gauge.medium`)
2. мини-график CPU (8–12 столбиков, ~34×14 pt, рисуется в `NSImage`)
3. `CPU 23%`
4. `RAM 59%`
5. `58°` (температура CPU)
6. `↓2.4M ↑120K`

По умолчанию: CPU % + температура. Если ничего не выбрано — показывается иконка. Текст — моноширинные цифры (`monospacedDigitSystemFont`), чтобы ширина не прыгала. Значение, по которому сейчас активно правило оповещения, рисуется красным (`NSAttributedString`). Клик левой кнопкой открывает/закрывает панель.

### 4.2 Панель (`NSPopover`, ширина ~360 pt)

Сверху сегментированный переключатель вкладок (иконки SF Symbols с подсказками), снизу строка «⚙ Настройки · Выход».

| Вкладка | Содержимое |
|---|---|
| **Обзор** | сетка плиток 2×N: CPU, Память, Температура, GPU, Сеть, Диск — у каждой крупное значение и мини-график за 10 минут; плитка Батарея на всю ширину (если есть батарея); ниже топ-5 процессов по CPU |
| **CPU** | график общей загрузки, графики P- и E-кластеров, столбики по каждому ядру (P и E разным цветом) |
| **Память** | график использования, разбивка app/wired/compressed/cached, давление памяти, swap |
| **Сеть** | графики ↓ и ↑, суммарный трафик с запуска, активный интерфейс |
| **Диск** | графики чтения/записи, список томов со шкалой заполненности |
| **Сенсоры** | все температурные датчики, вентиляторы, загрузка GPU, мощность системы, батарея (заряд, циклы, здоровье, Вт) |
| **Процессы** | полный список процессов, сортировка по CPU или памяти (переключатель), до 50 строк |

Плитки и значения, по которым активно оповещение, подсвечиваются красным. Недоступные значения — «—»; плитка/секция полностью недоступной метрики скрывается (например, Батарея на десктопе, вентиляторы на MacBook Air).

### 4.3 Окно настроек

Отдельное окно (`NSWindow` с SwiftUI `SettingsView`), три раздела:

- **Общие:** интервал обновления (1 / 2 / 5 с, по умолчанию 2), автозапуск при входе (`SMAppService.mainApp`, по умолчанию выключен).
- **Строка меню:** галочки для 6 элементов из 4.1.
- **Оповещения:** для каждого правила — переключатель и порог(и).

Хранение — `UserDefaults` через `SettingsStore` (`@Observable`), изменения применяются сразу.

## 5. Оповещения

### 5.1 Правила по умолчанию

| Правило | Условие | Длительность |
|---|---|---|
| `cpuTemperature` | температура CPU > 95 °C | ≥ 30 с |
| `cpuLoad` | общая загрузка CPU > 90 % | ≥ 60 с |
| `memoryPressure` | давление памяти = critical | сразу |
| `diskSpace` | свободно на системном томе < 10 ГБ | сразу |

Порог и длительность каждого правила редактируются в настройках; правило можно выключить.

### 5.2 `AlertEngine` (в `MetricsCore`, чистая логика)

- Вход: `Snapshot`, текущее время (`now` передаётся параметром → тестируемость), список правил.
- Для каждого правила хранит момент, с которого условие непрерывно истинно. Если условие истинно ≥ длительности — правило **активно**.
- Выход: множество активных правил (для подсветки) и список событий «отправить уведомление».
- Уведомление по правилу отправляется при переходе в активное состояние, и затем повторно не чаще чем раз в 10 минут, пока правило остаётся активным.
- Если значение метрики `nil` — условие считается ложным (таймер сбрасывается).

### 5.3 Доставка

Протокол `AlertNotifier { func notify(_ event: AlertEvent) }`. Реализация в приложении — `UNUserNotificationCenter`; разрешение запрашивается при первом включённом правиле. Если разрешение не дано или центр уведомлений недоступен (ad-hoc подпись), работает только красная подсветка — ошибка логируется, приложение не падает.

## 6. Обработка ошибок

- Каждый сборщик: любая ошибка API → `nil`, без исключений наружу. Повторная попытка — на следующем тике.
- Приватные API ищутся динамически там, где возможно (`dlsym`), чтобы отсутствие символа давало `nil`, а не падение при запуске.
- Счётчики (сеть, диск, CPU-время процессов) могут уменьшиться (сброс интерфейса, перезапуск процесса с тем же pid) — отрицательная дельта трактуется как «нет данных» для этого тика.
- Логирование через `os.Logger` (subsystem `local.statusapp`), без спама: ошибка конкретного сборщика логируется один раз до первого успешного чтения.

## 7. Тестирование

- **Юнит-тесты (`MetricsCoreTests`, Swift Testing — `import Testing`, `@Test`, `#expect`; запуск `swift test`):**
  - `RingBuffer`: добавление, переполнение, порядок элементов.
  - `RateCalculator`: перевод счётчиков в скорость/проценты, первый тик → `nil`, отрицательная дельта → `nil`.
  - Расчёт CPU % из тиков (`user+system+nice` / total), раздельно по P/E.
  - `AlertEngine` с подменяемым временем: длительность, сброс при `nil`/ложном условии, пауза 10 минут между повторными уведомлениями, немедленные правила.
  - Форматтеры: байты/скорости (Б, КБ, МБ, ГБ), проценты, температура.
- **Smoke-тесты сборщиков** на реальной машине: два вызова `sample()` с паузой; значение либо `nil`, либо в разумных пределах (CPU 0–100 %, температура 10–120 °C, память used ≤ total, процессов > 0).
- **Ручная проверка UI:** сборка `.app`, запуск, скриншоты строки меню и всех вкладок панели, проверка подсветки через временно заниженный порог.

## 8. Сборка и запуск

`scripts/build-app.sh`:

1. `swift build -c release`
2. собрать `build/StatusApp.app/Contents/{MacOS,Resources,Info.plist}`
3. `codesign --force -s - build/StatusApp.app`

Bundle id: `local.statusapp.StatusApp`. `LSUIElement = YES`. Установка — копированием в `/Applications` вручную (автозапуск через `SMAppService` надёжнее работает из `/Applications`).
